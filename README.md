## О проекте

Linux-утилита `readmem` предназначена для специалистов по информационной безопасности и может использоваться как вспомогательный инструмент для чтения виртуального адресного пространства процесса по его идентификатору (PID) и извлечения строк заданного формата.

**Ключевые возможности:**

- выполнение одного прохода или циклический просмотр памяти с заданной периодичностью;
- поиск по регулярным выражениям и полному вхождению подстроки;
- объединение нескольких условий поиска;
- исключение ненужных областей памяти и строковых значений;
- вывод новых, исчезнувших или всех совпадений;
- сохранение результата в текстовом формате, TSV или JSON Lines;
- осуществление предварительного исследования строк без заранее составленного условия.

> Используйте `readmem` только в отношении сервисов, на исследование которых у вас есть
> разрешение. Память процесса и созданные файлы могут содержать пароли, 
> ключи, маркеры доступа, персональные данные и другие конфиденциальные сведения.

## Сборка

**Для получения готового статического исполняемого файла необходимы:**

- компилятор `C` с поддержкой `C17` и библиотекой `musl`;
- GNU Make;
- `strip` из набора `binutils`.

**Пример для Debian и Ubuntu:**

```bash
sudo apt-get update
sudo apt-get install --no-install-recommends build-essential musl-tools binutils file

make release
```

Результат будет сохранён в каталоге `dist`:

```text
dist/readmem-linux-ARCH
```

Имя архитектуры определяется командой `uname -m`. Для установки утилиты под
коротким именем:

```bash
sudo install -m 0755 "dist/readmem-linux-$(uname -m)" /usr/local/bin/readmem
readmem --version
```

## Быстрый старт

Один проход с поиском точного вхождения подстроки:

```bash
sudo readmem \
  --pid 1234 \
  --contains 'administrator' \
  --emit all \
  --format text \
  --best-effort
```

Периодический поиск новых значений раз в секунду:

```bash
sudo readmem \
  --pid 1234 \
  --interval 1s \
  --regex '.*(hvs\.[[:alnum:]]{24}).*' \
  --emit new \
  --dedupe value \
  --exclude-map '\.db$' \
  --format jsonl \
  --output results.jsonl \
  --best-effort
```

Совпадения записываются в `results.jsonl`, а диагностические сообщения в
стандартный поток ошибок. Привилегии `sudo` требуется не всегда: возможность чтения зависит от владельца целевого процесса и настроек безопасности системы.

По умолчанию файл результатов содержит только найденные значения. Чтобы вместе с
ними записывать время, PID, адрес, имя области, а также служебную информацию о проходах и циклах, добавьте `--debug` (этот параметр предназначен только для формата JSON
Lines).

Путь, заданный через `--output`, должен отсутствовать: утилита создаёт новый файл
с правами `0600` и не перезаписывает существующие данные. Для осознанного
продолжения ранее созданного файла `readmem` используйте `--append`. Обычное
перенаправление стандартного вывода в файл отклоняется (для файлов всегда
указывайте `--output`).

Перед `--append` убедитесь, что путь относится именно к ранее созданному файлу
результатов. Используйте отдельный каталог, недоступный для записи другим
пользователям: явное дополнение существующего файла является осознанной
операцией и не позволяет утилите определить его назначение только по содержимому.

Без задания интервала повторного чтения `--interval` выполняется один проход. 
Если интервал указан без `--iterations` и `--duration`, просмотр продолжается до получения SIGINT или SIGTERM. В периодическом режиме по умолчанию действует стратегия `continue`:
если предел одного прохода достигнут, следующий проход продолжает чтение с
первого ещё не обработанного адреса.

## Режим исследования строк

Режим `--discover` извлекает все строки, удовлетворяющие требованиям к кодировке,
длине и областям памяти. Он помогает увидеть возможные значения перед составлением
регулярных выражений.

Пример исследования в течение 30 секунд:

```bash
sudo readmem \
  --pid 1234 \
  --discover \
  --interval 1s \
  --duration 30s \
  --emit new \
  --dedupe value \
  --min-length 6 \
  --max-length 512 \
  --exclude-map '\.db$' \
  --format jsonl \
  --output candidates.jsonl \
  --max-output-size 100M \
  --best-effort
```

Для `--discover` действуют следующие правила:

- необходимо явно указать `--output FILE` (вывод в терминал запрещён);
- режим нельзя объединять с положительными `--regex` и `--contains`;
- исключающие условия `--exclude-regex` и `--exclude-contains` разрешены;
- периодический просмотр должен иметь `--duration` или конечное `--iterations`;
- если `--max-output-size` не указан, применяется предел 100 Мб;
- существующий файл по умолчанию не принимается (для продолжения добавьте
  `--append`);
- существующий файл не очищается, а его размер входит в установленный предел;
- очередная запись сохраняется целиком либо не сохраняется вообще;
- достижение предела размера считается штатным завершением с кодом `0`.

Параметр `--duration` прекращает запуск новых проходов. Уже начавшийся проход ограничен значениями `--scan-timeout` и `--max-scan-size`. Если работа закончилась до
завершения текущего цикла просмотра, журнал JSON Lines содержит
`cycle_complete=false`.

За один запуск применяется одна кодировка. Для поиска строк UTF-16LE выполните
отдельный проход с `--encoding utf16le`. Файл исследования следует удалить сразу
после подготовки условий поиска.

## Основные параметры
### Процесс и периодичность

| Параметр                  | Назначение                                                                                                                            |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `-p, --pid PID`           | идентификатор исследуемого процесса                                                                                                   |
| `-i, --interval DURATION` | промежуток между началами проходов: `500ms`, `10s`, `2m`, `1h`                                                                        |
| `--duration DURATION`     | прекратить запуск новых проходов через указанное время                                                                                |
| `--iterations N`          | число проходов (`0` означает отсутствие ограничения)                                                                                  |
| `--scan-timeout DURATION` | наибольшее время одного прохода                                                                                                       |
| `--max-scan-size SIZE`    | наибольший объём чтения за проход (по умолчанию `256 Мб`                                                                              |
| `--scan-strategy MODE`    | `continue` - продолжать незавершённый цикл со следующего адреса, `restart` - каждый проход начинать сначала (по умолчанию `continue`) |
| `--max-memory SIZE`       | предел виртуальной памяти самой утилиты (по умолчанию `512 Мб`)                                                                       |
### Условия поиска

| Параметр                  | Назначение                                          |
| ------------------------- | --------------------------------------------------- |
| `--discover`              | извлекать строки без положительного условия поиска  |
| `-e, --regex PATTERN`     | регулярное выражение POSIX ERE (можно повторять)    |
| `-s, --contains TEXT`     | точная подстрока для поиска (можно повторять)       |
| `--match-mode MODE`       | объединение положительных условий: `any` или `all`  |
| `--exclude-regex PATTERN` | исключающее регулярное выражение (можно повторять)  |
| `--exclude-contains TEXT` | исключающая буквальная подстрока (можно повторять)  |
| `--encoding ENCODING`     | `ascii`, `utf8` или `utf16le`; по умолчанию `ascii` |
| `--min-length N`          | наименьшая длина строки; по умолчанию `4`           |
| `--max-length N`          | наибольшая длина строки; по умолчанию `4096`        |
### Области памяти

| Параметр              | Назначение                                                  |
| --------------------- | ----------------------------------------------------------- |
| `--include-map REGEX` | читать только области с подходящим именем (можно повторять) |
| `--exclude-map REGEX` | исключить области с подходящим именем (можно повторять)     |
### Вывод и состояние

| Параметр                 | Назначение                                                                            |
| ------------------------ | ------------------------------------------------------------------------------------- |
| `-o, --output FILE`      | добавить результаты в файл (`-` означает стандартный вывод)                           |
| `--append`               | продолжить существующий обычный файл `0600`, принадлежащий текущему пользователю      |
| `--format FORMAT`        | `text`, `tsv` или `jsonl` (по умолчанию `jsonl`)                                      |
| `--emit MODE`            | `all`, `new` или `changes` (по умолчанию `new`)                                       |
| `--dedupe MODE`          | удаление повторов: `none`, `value` или `address`                                      |
| `--state-file FILE`      | файл состояния для продолжения после перезапуска                                      |
| `--max-results N`        | наибольшее число результатов, хранимых в памяти                                       |
| `--max-output-size SIZE` | предельный размер выходного файла (по умолчанию `100 Мб`)                             |
| `--max-state-size SIZE`  | предельный размер файла состояния (по умолчанию `128 Мб`)                             |
| `--min-free-space SIZE`  | неприкосновенный остаток места в файловой системе (по умолчанию `64 Мб`)              |
| --debug                  | добавлять к найденным значениям полные свойства и служебную информацию `scan_summary` |
### Обработка ошибок и справка

| Параметр        | Назначение                                              |
| --------------- | ------------------------------------------------------- |
| `--best-effort` | продолжить после ошибок чтения отдельных страниц памяти |
| `-v, --verbose` | выводить подробные сведения о каждом проходе            |
| `-q, --quiet`   | не выводить предупреждения и информационные сообщения   |
| `-h, --help`    | показать краткую справку                                |
| `--version`     | показать версию программы                               |

## Регулярные выражения

Параметр `--regex` использует расширенные регулярные выражения POSIX (POSIX ERE) из
системной библиотеки `C`. Выражение проверяется относительно всей извлечённой строки.
Заключайте его в одинарные кавычки, чтобы командная оболочка не обрабатывала `$`,
`*`, квадратные скобки и обратные косые черты.

| Конструкция         | Значение                       | Пример                               |
| ------------------- | ------------------------------ | ------------------------------------ |
| `.`                 | любой символ                   | `'user.'`                            |
| `*`, `+`, `?`       | количество повторений          | `'ab+c'`                             |
| `{m}`, `{m,n}`      | заданное количество повторений | `'[[:digit:]]{4,8}'`                 |
| `[...]`, `[^...]`   | набор символов и его отрицание | `'[A-F0-9]+'`                        |
| `[[:digit:]]`       | цифра                          | `'id=[[:digit:]]+'`                  |
| `[[:alnum:]]`       | буква или цифра                | `'[[:alnum:]_-]+'`                   |
| `(...)`             | группировка                    | <code>'(admin&#124;root)'</code>     |
| <code>&#124;</code> | один из вариантов              | <code>'(active&#124;pending)'</code> |
| `^`, `$`            | начало и конец строки          | `'^token=[A-F0-9]+$'`                |

Поиск значения вида `data:abc-123`:

```bash
readmem --pid 1234 --regex '^data:[[:alnum:]_-]+$' --emit all
```

Поиск слова внутри более длинной строки:

```bash
readmem --pid 1234 --regex '.*administrator.*' --emit all
```

Поиск строки, похожей на адрес IPv4:

```bash
readmem --pid 1234 \
  --regex '^([[:digit:]]{1,3}\.){3}[[:digit:]]{1,3}$' \
  --emit all
```

Это выражение проверяет структуру, но не ограничивает каждую группу диапазоном
от 0 до 255.

Расширения PCRE не поддерживаются: `\d`, `\w`, `\s`, предварительные и
ретроспективные проверки, `(?:...)`, ленивые повторители и обратные ссылки.
Вместо `\d` используйте `[[:digit:]]`.

## Логические условия

Положительные `--regex` и `--contains` можно повторять и сочетать. Режим
`--match-mode any` используется по умолчанию и требует выполнения хотя бы одного
положительного условия, а `--match-mode all` каждого из них.

Все `--exclude-regex` и `--exclude-contains` являются исключающими: строка
отбрасывается, если сработало хотя бы одно из них.

Итоговое правило:

```text
(любое или все положительные условия) И НЕ (любое исключающее условие)
```

`administrator` или `root`:

```bash
readmem --pid 1234 \
  --contains 'administrator' \
  --contains 'root' \
  --match-mode any
```

Одновременное наличие `administrator` и `active`:

```bash
readmem --pid 1234 \
  --contains 'administrator' \
  --contains 'active' \
  --match-mode all
```

`administrator` или `root`, одновременно `active`, но не `disabled`:

```bash
readmem --pid 1234 \
  --regex '.*(administrator|root).*' \
  --contains 'active' \
  --match-mode all \
  --exclude-contains 'disabled'
```

В обычном режиме требуется хотя бы одно положительное условие. В режиме
`--discover` положительные условия не используются, но исключающие разрешены.

## Повторные проходы

Без `--interval` утилита выполняет один проход. При наличии интервала после
завершения каждого прохода выдерживается указанная пауза (проходы не выполняются
одновременно). Поэтому медленный просмотр не превращается в непрерывную нагрузку
на процесс и накопитель.

Проход - это одна итерация работы, ограниченная параметрами `--max-scan-size` и
`--scan-timeout`. Цикл - последовательность проходов, которая обработала все
выбранные доступные для чтения области памяти.

По умолчанию используется `--scan-strategy continue`. Если один проход достиг
предела размера или времени, `readmem` сохраняет адрес и незавершённое состояние
извлечения строки. После паузы следующий проход продолжает текущий цикл с этого
места. Поэтому строка, пересекающая границу двух проходов, не теряется. После
достижения конца списка областей цикл завершается, а следующий начинается с
начала обновлённого `/proc/PID/maps`.

Если область, на которой остановилось чтение, исчезла или изменила границы до
следующего прохода, сохранённая незавершённая строка отбрасывается, новая область
читается с начала, а цикл помечается неполным.

Например, при размере выбранных областей 700 Мб и пределе 256 Мб первый цикл
занимает три прохода:

```text
цикл 1: проход 1 - 256 МиБ
цикл 1: проход 2 - 256 МиБ
цикл 1: проход 3 - оставшиеся области, cycle_complete=true
цикл 2: проход 4 - снова с начала
```

При `restart` каждый проход начинается с первой подходящей области. Если общий
объём превышает установленный предел, поздние области не будут просмотрены. Этот
режим нужен только тогда, когда важнее часто проверять начало адресного
пространства, чем последовательно охватить его целиком.

Ограничить работу можно количеством проходов или временем (если заданы оба ограничения, работа прекращается при достижении первого из них):

```bash
readmem --pid 1234 --interval 2s --iterations 10 --contains token
readmem --pid 1234 --interval 2s --duration 1m --contains token
```

Режимы вывода:

- `--emit all` - выводить все совпадения после каждого прохода;
- `--emit new` - выводить значение только при первом обнаружении;
- `--emit changes` - выводить события появления `found` и исчезновения `lost`.

Удаление повторов:

- `--dedupe none` - считать каждое обнаружение отдельным результатом;
- `--dedupe value` - объединять одинаковые значения;
- `--dedupe address` - учитывать адрес и значение.

Параметр `--state-file` сохраняет сведения между перезапусками `readmem`, пока исследуемый процесс продолжает работать. Файл содержит контрольную сумму параметров поиска, PID и время запуска процесса. Состояние другого процесса, даже получившего тот же PID, не загружается.

Позиция незавершённого цикла хранится только в памяти работающего экземпляра
`readmem`. После перезапуска утилиты чтение начинается с первой выбранной области (файл состояния сохраняет удаление повторов, но не адрес продолжения).

В режиме `--emit changes` найденные значения накапливаются на протяжении всего
цикла. События `lost` формируются только после чистого завершения полного цикла.
Если хотя бы одна страница была пропущена, цикл прерван или работа закончилась до
его завершения, исчезновение строки не считается подтверждённым.

## Формат JSON Lines

В формате `jsonl` каждая строка файла является отдельным объектом JSON, что
позволяет последовательно обрабатывать результаты, не загружая весь файл в память.
Без `--debug` объект содержит только найденное значение:

```json
{"value":"data:example"}
```

Исключение - режим `--emit changes`, где необходимо отличать появление значения
от исчезновения:

```json
{"event":"found","value":"data:example"}
{"event":"lost","value":"data:example"}
```

Если нужен файл непосредственно из строк без оболочки JSON, используйте
`--format text`.

С параметром `--debug` найденное значение получает полный набор свойств:

```json
{"type":"match","timestamp":"2026-08-14T09:15:00.123Z","scan":18,"cycle":6,"event":"found","complete":true,"pid":1234,"address":"0x7f1234102000","mapping":"[heap]","value":"data:example"}
```
Основные поля:

| Поле        | Значение                                                             |
| ----------- | -------------------------------------------------------------------- |
| `timestamp` | время события в UTC                                                  |
| `scan`      | порядковый номер прохода                                             |
| `cycle`     | номер полного обхода выбранных областей памяти                       |
| `event`     | `match`, `found` или `lost`                                          |
| `complete`  | был ли текущий цикл полностью и без пропусков завершён этим проходом |
| `pid`       | идентификатор процесса                                               |
| `address`   | виртуальный адрес начала строки                                      |
| `mapping`   | имя области памяти                                                   |
| `value`     | найденная строка                                                     |

С параметром `--debug` после каждого обработанного прохода записывается объект
`scan_summary`, даже если цикл завершился полностью и совпадений не найдено. Это
позволяет контролировать объём чтения, пропуски страниц и адрес продолжения:

```json
{"type":"scan_summary","timestamp":"2026-08-14T09:15:00.456Z","scan":17,"cycle":6,"complete":false,"cycle_finished":false,"cycle_complete":false,"scan_strategy":"continue","pid":1234,"bytes_read":268435456,"skipped_pages":0,"mappings_read":1,"unbacked_file_bytes":0,"limited_file_mappings":0,"next_address":"0x10400000","next_mapping":"/usr/local/bin/prog"}
```

Поля сводки:

- `cycle_finished=true` означает, что достигнут конец списка выбранных областей;
- `cycle_complete=true` означает, что цикл закончен без пропущенных страниц и
  других нарушений полноты;
- `next_address` и `next_mapping` указывают место продолжения; после окончания
  цикла они равны `null`;
- при стратегии `restart` адрес носит диагностический характер: следующий проход
  всё равно начнётся сначала.

Диагностические сообщения всегда направляются в стандартный поток ошибок и не
смешиваются с JSON Lines. Параметры `--debug` и `--verbose` независимы:
`--debug` управляет служебными объектами в файле результатов, а `--verbose` -
подробностью сообщений в стандартном потоке ошибок. `--debug` допускается только
совместно с `--format jsonl`.

## Доступ к памяти процесса

Доступ к чужому адресному пространству регулируется проверками `ptrace` в ядре
Linux. На результат влияют:

- владелец процесса;
- разрешение ядра на создание снимка памяти процесса;
- модуль безопасности Yama и параметр `ptrace_scope`;
- пространства имён процессов и пользователей;
- наличие возможности `CAP_SYS_PTRACE`;
- другие модули безопасности Linux.

Не устанавливайте `readmem` с признаком `setuid-root`. Предпочтительнее запускать
утилиту от того же пользователя, что и целевой процесс, либо выдавать только
необходимую системную возможность отдельной службе.

Чтение не создаёт единого снимка состояния на один момент времени: целевой процесс
продолжает менять память. Перед каждым проходом утилита заново читает
`/proc/PID/maps` и проверяет время запуска процесса до и после чтения, чтобы
обнаружить завершение процесса или повторное использование PID.

Служебные области `[vvar]`, `[vvar_vclock]` и `[vsyscall]` пропускаются. Они не
содержат пользовательских строк и могут возвращать ошибку чтения, несмотря на
признак доступности в `/proc/PID/maps`.

## Большие файловые отображения и конец файла

Размер области памяти, связанной с файлом, может значительно превышать текущий
размер файла. Например, система управления базой данных может зарезервировать
100 Гб виртуального пространства для файла размером 8 Гб. Целые страницы после
конца файла недоступны и возвращают ошибку через `process_vm_readv(2)`.

Утилита `readmem` определяет актуальный размер файла через
`/proc/PID/map_files/START-END` или `/proc/PID/root/PATH`, проверяет устройство и
номер файла, округляет доступную длину до размера страницы и пропускает остаток
области за концом файла. Размер проверяется заново при каждом проходе.

Подтверждённая область за концом файла не считается ошибкой и не делает проход
неполным. При `--verbose` выводится одно сообщение на ограниченную область.

Автоматическое ограничение не устраняет стоимость чтения реально существующей
части большого файла. Если содержимое баз данных не относится к исследованию,
исключите такие области:

```bash
readmem --pid 1234 \
  --contains administrator \
  --exclude-map '\.db$' \
  --scan-timeout 10s \
  --best-effort
```

Если искомые данные должны находиться только в куче процесса Go, используйте
положительный фильтр:

```bash
readmem --pid 1234 \
  --contains 'administrator' \
  --include-map '^\[anon: Go: heap\]$' \
  --best-effort
```

Параметры `--include-map` и `--exclude-map` используют POSIX ERE и могут повторяться.
Несколько включающих условий объединяются по правилу «или», а исключающие всегда
имеют преимущество.

## Строгий режим и `--best-effort`

Без `--best-effort` любая необъяснимая ошибка чтения доступной области завершает
проход с кодом `5`, а частичные результаты этого прохода отбрасываются. Такой режим
подходит, когда необходимо подтвердить отсутствие строки во всех выбранных
областях памяти.

С `--best-effort` недоступная страница пропускается, проход помечается как
неполный, а чтение продолжается. Размер пропуска определяется размером страницы
системы и обычно равен 4096 байтам. Последовательные ошибки объединяются в одно
сообщение с диапазоном адресов.

Уже найденные значения неполного прохода сохраняются. События `lost` для такого
прохода не создаются.

Для исследования активно изменяющихся процессов обычно удобнее `--best-effort`.
Строгий режим следует выбирать, когда важнее полнота прохода, чем получение
частичных результатов.

## Коды завершения

| Код | Значение                                                                               |
| --: | -------------------------------------------------------------------------------------- |
| `0` | успешное завершение, получение SIGINT/SIGTERM или достижение заданного предела размера |
| `1` | внутренняя ошибка программы                                                            |
| `2` | ошибка параметров командной строки                                                     |
| `3` | недостаточно прав для чтения памяти                                                    |
| `4` | целевой процесс завершился или PID был использован повторно                            |
| `5` | неполный проход в строгом режиме                                                       |
| `6` | ошибка выходного файла или файла состояния                                             |
